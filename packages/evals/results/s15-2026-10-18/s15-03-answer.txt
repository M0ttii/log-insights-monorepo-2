Hypotheses
- Single faulty node or rack: contradicted. The node and rack breadth check found the failure spread over 512 nodes [r_3f220b76.f12] and 32 racks [r_3f220b76.f13]. No node stands out.
- Job launch failed because the working directory was missing, and ciod then dropped its control connections: supported, not proven. The precursor check found ciod: LOGIN chdir(<PATH>) failed: No such file or directory in the 10 minutes before 6 [r_b7fe135c.f6] of 7 [r_b7fe135c.f1] episode starts. That is about 145.2× [r_b7fe135c.f9] its base rate. In the sampled burst it appears at −838.005 ms [r_864b4e0c.f18], for path /p/gb2/draeger/benchmark/dat32k_060205. This is a temporal association only. One episode had no such precursor, so the hypothesis doesn’t explain every burst.
- Problem on the front-end/service host 172.16.96.116: open. All sampled sockets go to that host, but I haven’t run a check that separates “the host dropped the connections” from “the job died and the host closed them”.
- Hardware: open, weak. Corrected DDR and L3 errors appear after some bursts, but only at roughly their background rate. They don’t look like a driver.
